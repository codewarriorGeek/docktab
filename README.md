# DockTab

A hands-free money assistant for truck drivers. The driver says what happened at the dock; DockTab bills detention, pays the lumper and answers "has the broker paid me?" through PayPal. Built for the [PayPal AI Hackathon](https://paypalaihackathon.devpost.com/).

**Live demo:** https://docktab.fawzai.com (works on a phone; tap the mic or one of the examples)

**Video (2:39):** https://youtu.be/EC-r_4r8Q24

The name: the **dock** is where drivers wait unpaid, and a **tab** is the running bill. DockTab keeps the tab for the time at the dock and makes sure someone pays it.

> Everything runs in the PayPal sandbox. No real money moves, and the brokers and the lumper are sandbox test accounts.

## The problem

Truck drivers are paid by the load, not by the hour. When a warehouse keeps a truck waiting at the dock past the free time in the rate confirmation (usually two hours), the carrier is owed detention pay. In practice drivers rarely collect it: they have to note the times, write an invoice after a long day, send it to the broker and chase it. At the same dock they often have to pay the unloading crew (the lumper) on the spot. DockTab turns both into one sentence spoken in the cab.

## What it does

| Driver says | DockTab does | PayPal |
|---|---|---|
| "I've been stuck at the Columbus dock all morning, bill the broker." | Works out billable detention from the truck's arrival, the appointment and the free time in the rate confirmation, then bills the broker with the dock timeline as evidence | Invoicing v2: create and send (PayPal Agent Toolkit) |
| "Lumper wants 150 dollars for load 1042." | Pays the unloading crew | Payouts |
| "Has Prairie paid me for Indianapolis?" then "Yes, remind them." | Checks the invoice, confirms what money actually arrived, and chases the broker | Agent Toolkit: list and get invoices, invoice reminder. PayPal Server SDK: Transaction Search |
| "Update the invoice." / "Cancel the Columbus invoice." / "Lakeshore paid by check." | Re-bills detention up to now, cancels a wrong invoice, or marks an invoice paid outside PayPal | Agent Toolkit: cancel sent invoice, record payment |

Guard rails for money: one open invoice per load (a second "bill them" says what was already billed), invoice amounts stay separate from the still-running detention clock, and a second lumper payout for the same load needs the driver to confirm. Each demo session cancels the invoices earlier sessions left open, so a broker never holds two open invoices for one load.

A dispatcher board next to the driver panel shows each load's detention clock, invoice status and lumper payout, refreshed from PayPal.

## How it works

- **An AI agent** plans each request and calls tools in a loop, with prompt caching on the fixed system prompt and tool list, so each call reads about 5k cached tokens. Amounts and times always come from code, never from the model.
- **PayPal Agent Toolkit** (`@paypal/agent-toolkit`) for invoices. Its tool schemas are handed to the agent directly for reads and reminders; creating and sending an invoice runs inside DockTab's own `bill_detention` tool so the amount is computed, not generated. Cancelling and recording outside payments go through DockTab's `cancel_invoice` and `record_payment` tools, which first check that the invoice belongs to one of the driver's loads and is still unpaid.
- **PayPal Server SDK** (`@paypal/paypal-server-sdk`, generated by APIMatic) for Transaction Search: the `paypal_activity` tool reports what money really moved in and out of the account. See below.
- **Payouts REST API** for the lumper, with a $500 demo cap.
- **Voice in the browser** with the Web Speech API (speech recognition and read-aloud); no extra service.
- **Next.js 16** (App Router). The agent's progress streams to the page as NDJSON, so the driver sees each PayPal call as it happens.
- Guardrails: sandbox-only base URL check, per-IP and global rate limits, a generic public health check.

## Built with the APIMatic Context Plugin for PayPal

The Transaction Search part was written with an AI coding assistant and the [APIMatic Context Plugin for PayPal](https://github.com/paypaldev/server-sdk-context-plugin-preview), installed into the assistant with:

```sh
npx context-plugins install https://github.com/paypaldev/server-sdk-context-plugin-preview --targets <your-assistant>
```

The plugin's TypeScript skills (`typescript-getting-started`, `typescript-authentication`, `typescript-calling-endpoints`, `typescript-error-handling`) gave the coding agent the SDK facts it needed instead of guesses: the npm package and version (2.5.0), the `Client` configuration with `clientCredentialsAuthCredentials`, the `TransactionSearchController.searchTransactions` parameters and response models, and the `ApiError` shape. The result is [`src/lib/paypal-sdk.ts`](src/lib/paypal-sdk.ts) and the check script [`scripts/sdk-check.mjs`](scripts/sdk-check.mjs).

It also explained a real bug. The authentication skill states that the SDK client keeps its OAuth token and fetches a new one before it expires (`oAuthClockSkew` renews it early). The Agent Toolkit used for invoices keeps a single token for the life of the process. On the hosted demo that token was eventually rejected, invoice lookups came back as 401 error payloads, and the page crashed. The fix: the Transaction Search client uses the SDK's own token handling, and [`src/lib/paypal.ts`](src/lib/paypal.ts) rebuilds the toolkit every 30 minutes and retries once on a 401.

## Run it locally

Requirements: Node.js 22, a PayPal developer sandbox app (Invoicing and Transaction search enabled, Payouts available) and an API key for the AI model.

```sh
npm install
cp .env.example .env.local   # fill in the PayPal sandbox app, sandbox account emails and the AI model key
npm run build && npm start
```

Checks before you start:

- `node --env-file=.env.local scripts/smoke.mjs`: PayPal token, order capture, invoice create and send
- `node --env-file=.env.local scripts/sdk-check.mjs`: Transaction Search through the PayPal Server SDK
